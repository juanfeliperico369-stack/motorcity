# X-3 · Carga por cercanía con dependencias directas

Sobre la implementación previa de ia/codex/carga-fisica. El catálogo de Run City contiene sectores [{id,url,x,z,dependencias}]. Construir CargadorSectores con catalogo: indice.sectores y baseUrl: URL absoluta de indice.json (necesaria para URLs relativas, no resolver respecto al Worker). El consumidor debe comunicar sectores visibles y posición en metros; rumbo 0 hacia +z. La prioridad es visible, dependencia directa, precarga por distancia y rumbo. No expandir dependencias recursivamente: una celda remota puede depender de toda la isla. El presupuesto incluye visibles y dependencias; si no alcanza, se rechaza el cambio sin degradación silenciosa. Reducir precarga, recortar entidades o aumentar presupuesto tras medir memoria.

estado() expone faltantes requeridos, cola, pendientes, caché y errores; alExpulsar(id,sector) permite liberar mallas y referencias. No retener mallas de sectores expulsados. Las respuestas obsoletas no se insertan; las solicitudes en curso se dejan completar. Reintento por actualización después de 1000 ms; no se crean temporizadores. El integrador debe manejar una caída fatal del Worker, errores de callbacks y un respaldo compatible con Android antiguo: no incluidos. No se construyen mallas aquí ni se cambia la copia motor/ del juego. El presupuesto de bytes por sector sigue en el Worker; el número de sectores no mide la memoria GPU.
